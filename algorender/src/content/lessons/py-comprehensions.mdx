<Section step="hook" title="A list-building loop in one line">

You have written this shape many times: start an empty list, loop, and `append` something on each turn. Python has
a shorter way to say it. A **comprehension** builds the whole list in one expression that reads almost like a
sentence: `[n * 2 for n in nums if n > 0]` is "n times 2, for each n in nums, if n is above 0".

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="comprehension">An expression in brackets that builds a new list, dict or set by looping: `[n * 2 for n in nums]`.</Term>
  <Term name="filter">An `if` at the end of a comprehension. Only the items that pass it go in; the rest are left out.</Term>
  <Term name="conditional expression">`a if c else b`: gives `a` when `c` is true, and `b` when it isn't. It always needs its `else`.</Term>
</Terms>

Here is a loop you know, and the comprehension that does the same job:

```python
squares = []
for n in range(5):
    squares.append(n * n)

squares = [n * n for n in range(5)]   # the same list: [0, 1, 4, 9, 16]
```

Read a comprehension as the loop it replaces: `for n in range(5)` is the loop, and the expression in front, `n * n`,
is what gets appended on each turn. Its `n` only exists inside the brackets, so it never changes an `n` outside.

An `if` can go in two places, and they do different jobs:

```python
nums = [4, -1, 0, 7]
[n for n in nums if n > 0]           # filter: [4, 7], the others are left out
[n if n > 0 else 0 for n in nums]    # choice: [4, 0, 0, 7], every item stays
```

At the end, `if` is a filter: the loop with an `if` around the `append`, deciding whether an item goes in at all. It
has no `else`. At the front, `n if n > 0 else 0` is a conditional expression: every item goes in, as `n` or as `0`,
and the `else` is required. Mix them up and Python won't run the line: `[n for n in nums if n > 0 else 0]` is a
`SyntaxError`, and so is `[n if n > 0 for n in nums]`.

Either way, `nums` doesn't change: a comprehension builds a **new** list, which you keep by pointing a name at it.
Curly brackets build a dict (with a colon, `key: value`) or a set (without one):

```python
words = ["apple", "fig", "kiwi"]
lengths = {w: len(w) for w in words}            # {'apple': 5, 'fig': 3, 'kiwi': 4}
remainders = {n % 3 for n in [3, 4, 5, 6, 7]}   # {0, 1, 2}: each one once
```

A comprehension is for **building** a collection. To do something with each item, like printing it, write a loop:
`[print(w) for w in words]` prints the words, but also builds a list of `None`s nobody wants. And when each item
needs several steps, a loop with a line per step reads better.

</Section>

<KeyIdea>

**A comprehension is a loop that builds a new collection: `[expression for item in items if condition]`.** The
expression in front is what goes in, and an `if` at the end decides whether it goes in at all.

</KeyIdea>

An `if` at the end only says whether an item goes in, so an `else` has nothing to do there, and Python rejects the
line. To keep every item but change some, put a conditional expression at the **front**:
`[n if n > 0 else 0 for n in nums]`.

</Misconception>

A comprehension builds a **new** list and leaves the old one alone; on a line of its own, it builds a list and throws
it away. Point a name at the result to keep it, even the old name: `nums = [n * 2 for n in nums]`.

<Section step="recap" title="What to remember">

- `[expr for x in xs]` builds a new list: read it as the loop with `append(expr)` inside.
- An `if` at the end is a filter: items that fail it are left out.
- `a if c else b` at the front is a choice: every item goes in, and the `else` is required.
- `{k: v for ...}` builds a dict, and `{x for ...}` a set.
- A comprehension never changes the list it loops over; point a name at its result to keep it.
- Use a plain loop for doing things, like printing, and for logic that takes several steps.

</Section>
