<Section step="hook" title="Highest score first, ties A to Z">

A leaderboard puts the highest score at the top and lists tied players by name. Python sorts in one line, but there
are two ways to ask: one makes a new list and leaves yours alone, the other rearranges the list you have.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="sorted()">Returns a **new** list of a collection’s items in order, and leaves the collection as it was.</Term>
  <Term name="in place">Changing an object itself rather than making a new one, as `append` does.</Term>
  <Term name=".sort()">A list method that sorts the list in place and, like `append`, gives back `None`.</Term>
  <Term name="key=">As with `max` and `min`: a function called on each item; the items go in order of what it gives back.</Term>
  <Term name="stable">Items that tie keep the order they had. Python’s sorts always do.</Term>
</Terms>

```python
nums = [3, 1, 2]
new = sorted(nums)          # new is [1, 2, 3]; nums is still [3, 1, 2]
nums.sort()                 # now nums itself is [1, 2, 3]
sorted(nums, reverse=True)  # [3, 2, 1]: biggest first
```

`sorted` takes any collection (a tuple, a string, a set, a dict) and always gives back a list. Because `.sort()` gives
back `None`, `nums = nums.sort()` sorts the list, then points `nums` at `None`, and the list is lost.

**Sorting by something else.** With `key=`, Python sorts by the function’s answers, but keeps the items
themselves:

```python
sorted(["plum", "kiwi", "fig"], key=len)   # ['fig', 'plum', 'kiwi']
```

`plum` and `kiwi` tie on length, and stability keeps them in the order they came.

**Capitals.** Strings are compared character by character, and each character has a number, its **character code**.
Every capital, `A` to `Z`, has a smaller code than every small letter, so capitals come first:

```python
sorted(["amy", "Zoe", "ben"])                 # ['Zoe', 'amy', 'ben']
sorted(["amy", "Zoe", "ben"], key=str.lower)  # ['amy', 'ben', 'Zoe']
```

`str.lower` is the string method `lower` as a function: `str.lower("Zoe")` gives `"zoe"` (string methods are the next
topic). Sorting by the small-letter version gives dictionary order.

**Sorting by several things.** Tuples compare item by item, moving on only when items tie, so a
tuple key sorts by its first item and breaks ties with the next. For score high to low, then name A to Z,
make the score negative, so the biggest score is the smallest key:

```python
players = [("Ola", 7), ("Ben", 9), ("Ade", 7)]
sorted(players, key=lambda p: (-p[1], p[0]))
# [('Ben', 9), ('Ade', 7), ('Ola', 7)]
```

`reverse=True` wouldn’t do here: it flips everything, so the names would come Z to A.

**Dicts.** Sorting a dict gives its keys, and `sorted(d.items())` gives its `(key, value)` pairs in order of
key; `key=lambda kv: kv[1]` orders them by value.

</Section>

<KeyIdea>

**`sorted(xs)` makes a new list; `xs.sort()` changes `xs` itself and gives back `None`.** Both take `reverse=True` and
`key=`, a function whose answers decide the order; a tuple key sorts by its first item and breaks ties with the next.

<Section step="recap" title="What to remember">

- `sorted(xs)` returns a new list and leaves `xs` alone.
- `xs.sort()` sorts the list in place and gives back `None`, so never write `xs = xs.sort()`.
- `reverse=True` flips the order; `key=` sorts by a function’s answer for each item, and a tuple key such as
  `lambda p: (-p[1], p[0])` sorts by score high to low, then name.
- Sorting is stable, and capitals come before small letters unless you sort with `key=str.lower`.
- Sorting a dict gives its keys; `sorted(d.items())` gives its pairs.

</Section>
