<Section step="hook" title="Every sat-nav asks this question">

What is the shortest route from A to F, when roads have different lengths? Breadth-first search answers it when every road
is the same length, because it explores in rings of "one step away", "two steps away"… With lengths, the nearest node is
no longer the one with the fewest steps.

Dijkstra's idea is to keep exploring in rings, but rings of **distance**: always handle the closest node you haven't
finished yet. Once a node is the closest unfinished one, nothing can ever give it a shorter route, so you can **settle**
it for good.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="dist[v]">The best distance from the start to v found so far. Starts at ∞ for everything except the start (0).</Term>
  <Term name="settled">A node whose distance is final. Each node is settled exactly once.</Term>
  <Term name="relaxation">Checking an edge u → v: if dist[u] + w beats dist[v], update dist[v] and remember u as v's predecessor.</Term>
  <Term name="min-heap">A priority queue that hands back the unsettled node with the smallest tentative distance.</Term>
</Terms>

</Section>

<Section step="see" title="Watch the distances settle">

<Explore slug="dijkstra" settings={{ preset: 'roads' }} caption="Nodes are settled in increasing order of distance: 0, 2, 3, 8, 10, 13. At the end, following prev from F gives the route." />

Watch the heap panel: a node can be pushed several times as its distance improves. The older, larger entries become stale
and are skipped when popped. That "lazy" approach is simpler than updating entries in place.

<KeyIdea>

When a node is popped from the heap with the smallest distance, every other route to it has to leave the settled region
through a node at least that far away, and **edges never shorten a route**. So its distance can't improve: it is final.
That argument is the whole proof, and its one assumption is that no edge is negative.

</KeyIdea>

</Section>

It needs every edge to be non-negative. With negative edges use **Bellman–Ford**, which relaxes every edge V − 1 times and
can even detect a negative cycle, where no shortest path exists at all.

  title="Follow the lightest edge from the node you just settled"
  probes={[

      answer: 2,
      trap: 0,
      why: 'Dijkstra settles the unsettled node closest to the start, wherever it hangs. A is 4 away, closer than D at 9, even though A was reached from S, not from B.',
    },
    {
      q: 'Why does Dijkstra compare every unsettled node, not just the neighbours of the node it just settled?',
      choices: ['It doesn’t: following the cheapest edge from the newest node is enough', 'The closest unsettled node may hang off a node settled earlier', 'Every node has to be visited twice'],
      answer: 1,
      trap: 0,
      why: 'What matters is the total distance from the start. The node with the smallest total can be a neighbour of any settled node, so the heap holds all of them.',
    },
  ]}
>

Dijkstra doesn't walk from node to node. It picks the unsettled node with the smallest **total distance from the start**,
which may hang off any node settled earlier. Always taking the cheapest edge out of the newest node is a greedy walk: a
short edge at the end of a long route can still be further away than a node you passed earlier.

</Misconception>

<Section step="recap" title="What to remember">

- Dijkstra settles nodes in increasing order of distance, relaxing each settled node's edges.
- A min-heap finds the closest unsettled node in O(log V); stale entries are skipped.
- It is correct **only without negative edges**; Bellman–Ford handles those.
- It is breadth-first search with "rings of distance" instead of "rings of steps", and the basis of routing and A* search.

</Section>
