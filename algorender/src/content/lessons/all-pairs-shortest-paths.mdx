<Section step="hook" title="Every distance at once">

Old road atlases end with a table of driving distances between every pair of big cities. Fifty cities make 1,225
pairs. Running [Dijkstra's algorithm](/learn/dijkstra) once from each city would fill it, as long as no road
has a negative length.

**Floyd–Warshall** fills the whole table in one go, with three loops and a single comparison, and it copes with
negative lengths as long as no cycle adds up below zero. Its trick comes from
[dynamic programming](/learn/dynamic-programming): answer a smaller question first. Here the smaller question limits
which cities a route may pass through, and each round allows one more.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="distance matrix d">A V × V table: d[i][j] is the shortest distance found so far from i, the row, to j, the column.</Term>
  <Term name="stop-over">A node a route passes through between its two ends. A → C → D → B has two stop-overs, C and D.</Term>
  <Term name="round k">One pass over every pair (i, j) that also allows node k as a stop-over. There are V rounds, one per node.</Term>
  <Term name="negative cycle">A cycle whose weights add up to less than 0. Going round it once more always makes a route shorter, so a route that can take that detour has no shortest length.</Term>
  <Term name="next-hop matrix">next[i][j], the first step on the best path from i to j, kept beside d so the paths themselves can be read back.</Term>
</Terms>

</Section>

<Section step="see" title="One more stop-over each round">

Floyd–Warshall fills a dynamic programming table, built from the usual four decisions:

- **State:** after round k, d[i][j] is the length of the shortest path from i to j whose stop-overs are all k or nodes
  before it (in the visualiser, the nodes go in order A, B, C…).
- **Base case:** before any round no stop-over is allowed, so d holds the direct edges: the weight where there is one,
  0 on the diagonal and ∞ everywhere else.
- **Recurrence:** the best path that may also use node k either avoids k, so d[i][j] stays, or passes through k
  once. Then it splits into i to k and k to j, neither of which stops over at k, so both are already in the table:
  d[i][j] = min(d[i][j], d[i][k] + d[k][j]).
- **Fill order:** k is the outer loop. Every pair finishes round k before any pair starts round k + 1.

<Explore slug="floyd-warshall" settings={{ preset: 'classic' }} caption="Four cities, seven one-way roads. 22 pairs are checked and 11 improve. d[B][D] falls from ∞ to 15 in round A (B → A → D), then to 3 in round C (B → C → D). d[B][A] falls from 8 to 7 in round C and to 5 in round D: B → C → D → A, a route with two stop-overs." />

Row k and column k hold the two halves of every route through k. The visualiser checks only the pairs that could
improve, where i reaches k and k reaches j; the plain loops make 4 × 4 × 4 = 64 tests here.

<KeyIdea>

**After round k, d[i][j] is the shortest path from i to j that stops over only at k and the nodes before it. Round k
joins a best path to k with a best path from k, both already in the table: d[i][j] = min(d[i][j], d[i][k] + d[k][j]).**
With k as the outer loop, V rounds of V² pairs find every distance in Θ(V³) time, with one V × V matrix.

</KeyIdea>

</Section>

<Section step="do" title="The loops in code, and what can go wrong">

Here is one round in code, with k = 1, on three nodes numbered 0 to 2. 99 stands for "no edge", since it is bigger
than any real distance here. The full algorithm wraps these two loops in a third, over k = 0, 1, 2.

  answer={1}
  why="At i = 2, j = 0 the test adds d[2][1] + d[1][0] = 1 + 6 = 7, which beats 99. The same round lowers d[0][2] from 9 to 4 + 2 = 6. Round 0 before it and round 2 after it change nothing, so the printed rows, 0 4 6, 6 0 2 and 7 1 0, are the final distances."
/>

The round tests row 1 and column 1 too, and never changes them. That holds in every round: d[i][k] could only become
d[i][k] + d[k][k], and d[k][k] is 0. So every pair reads the same two halves whether other cells have been updated
yet or not, which is why one matrix, overwritten in place, is enough.

  id="k-any-loop"
  title="The three loops can go in any order"
  probes={[

      choices: ['6, along B → D → C → A', '∞: no route is found', '2, the edge B → D'],
      answer: 1,
      trap: 0,
      why: 'When d[B][A] is decided, d[B][C] (later in row B) and d[D][A] (in row D) are still ∞, so no k joins two known halves and the route of 6 is never found. With k outermost, it would be.',
    },
    {
      q: 'Which loop must be the outermost in Floyd–Warshall?',
      choices: ['k, the stop-over', 'i, where the route starts', 'Any of them: the loops are interchangeable'],
      answer: 0,
      trap: 2,
      why: 'Round k needs d[i][k] and d[k][j] to be the best routes through the earlier nodes, which holds only if every pair finishes one round before the next begins.',
    },
  ]}
>

The recurrence trusts d[i][k] and d[k][j] to be the best routes through the earlier nodes, which holds only if every
pair finished those rounds first. Put i or j outermost and each d[i][j] is settled for good from cells that haven't
had their rounds yet. On the one-way chain A → C → D → B, each edge weighing 1, the order i, j, k reaches d[A][B]
while d[A][D] and d[C][B] are still ∞, and never finds the route of length 3. Inside a round, i and j can go in
either order.

</Misconception>

Unlike Dijkstra, Floyd–Warshall settles nothing early: every pair is tested again each round, so negative edges are
fine.

<Explore slug="floyd-warshall" settings={{ preset: 'negative' }} caption="C → B weighs −1. Round C lowers d[A][B] from 4 to 1 (A → C → B), d[A][D] from 6 to 3 and d[D][B] from 7 to 4. The finished matrix keeps d[C][B] = −1, and every cell on the diagonal is still 0." />

A **negative cycle** is different: a route round it comes back cheaper than it left, so the diagonal drops below 0.

<Explore slug="floyd-warshall" settings={{ preset: 'cycle' }} caption="A → B → C → A weighs 1 − 2 − 1 = −2. d[C][C] drops to −2 in round B, and d[A][A] and d[B][B] follow in round C. The matrix also says d[A][D] = 1, but going round the cycle first gives −1, and twice gives −3." />

<Misconception
  id="negative-entry-cycle"
  title="A negative distance means a negative cycle"
  probes={[

    },
    {
      q: 'Which cells of the finished matrix show that a graph has a negative cycle?',
      choices: ['Any cell below 0', 'A cell on the diagonal, d[i][i], below 0', 'A cell still at ∞'],
      answer: 1,
      trap: 0,
      why: 'd[i][i] starts at 0 and drops only if some route leaves i and returns for a negative total, which is a negative cycle. Other negative cells just come from negative edges.',
    },
  ]}
>

Negative edges make negative distances, and they are correct: in Negative edge, d[C][B] stays −1. Only the diagonal
speaks about cycles. d[i][i] starts at 0 and falls only if a route leaves i and comes back for a negative total, so
check it after the last round: a d[i][i] below 0 means a negative cycle, and any distance whose route could detour
round it has no true value.

</Misconception>

The matrix gives lengths. For the routes, keep next[i][j] too: it starts as j wherever there is an edge, and whenever
d[i][j] improves through k it becomes next[i][k], since the new route starts the way the best route to k does. To read
a path, start at i and keep jumping to next[·][j] until you reach j. In Four cities, next[B][A] ends as C, next[C][A]
as D and next[D][A] as A: B → C → D → A.

Swap `min` for `or` and `+` for `and`, and the same loops say whether j can be reached from i at all:
`reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])`. That table is the graph's **transitive closure**.

Other algorithms fill the same table. [Dijkstra's algorithm](/learn/dijkstra) from every node costs O(V (V + E) log V)
with a binary heap, if no edge is negative; [Bellman–Ford](/visualisers/bellman-ford) from every node allows negative
edges at O(V² E). **Johnson's algorithm** combines them: one Bellman–Ford run gives each node a number h, reweighting
every edge u → v to w + h(u) − h(v) makes all weights non-negative without changing which paths are shortest, and
Dijkstra then runs from every node.

The loops run over nodes, not edges, so the plain code makes V³ tests whatever E is: 1,000 nodes cost a billion tests
with 2,000 edges or with 500,000. On a sparse graph with no negative edges, Dijkstra from every node costs about
V (V + E) log V, around 30 million steps for 1,000 nodes and 2,000 edges. Floyd–Warshall wins on small or dense
graphs, where its short loops are hard to beat.

</Misconception>

<Section step="recap" title="What to remember">

- d starts as the direct edges, 0 on the diagonal and ∞ elsewhere. Round k allows k as a stop-over:
  d[i][j] = min(d[i][j], d[i][k] + d[k][j]).
- After round k, d[i][j] is the shortest path stopping over only at k and the nodes before it; after all V rounds it
  is the true distance.
- k must be the outer loop. One matrix is enough, because round k never changes row k or column k.
- Negative edges are fine; a negative cycle shows as a d[i][i] below 0. A next-hop matrix recovers the paths.
- Θ(V³) time whatever the edges, Θ(V²) memory: best for small or dense graphs. On large sparse ones, run Dijkstra from
  every node, or Johnson's algorithm if some edges are negative.
- Next: practise with [Signal Spread Time](/practice/network-delay-time), a one-source problem for Dijkstra (what
  would Floyd–Warshall cost with up to 500 nodes?), and try your own graph on the
  [Floyd–Warshall](/visualisers/floyd-warshall) and [Bellman–Ford](/visualisers/bellman-ford) visualisers.

</Section>
