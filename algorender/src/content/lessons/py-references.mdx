<Section step="hook" title="Two names, one list">

You make a list of guests, then write `backup = guests` to keep the original safe, and append a late arrival to
`guests`. The backup has the late arrival too. Nothing went wrong with Python: `=` never copies a list. It gives the
same list a second name. Once you see names as arrows to objects, this stops being a surprise, and becomes something
you can use.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="reference">What a name holds: an arrow to an object. For a list it matters, because the object can change.</Term>
  <Term name="alias">A second name for the same object. A change made through one name shows through every other.</Term>
  <Term name="is">`a is b` asks whether two names point at the very same object.</Term>
  <Term name="==">`a == b` asks whether two values are equal: for lists, the same items in the same order.</Term>
  <Term name="copy">A new list with the same items: `a.copy()`, `a[:]` or `list(a)`.</Term>
</Terms>

`b = a` points `b` at the object `a` points at. For a list, which can change, that matters: `b.append(3)` changes
the one list, and `a` sees it too. To get a separate list, copy it:

```python
a = [1, 2]
b = a            # one list, two names: a is b
c = a.copy()     # a second list with the same items: a == c, but not a is c
b.append(3)      # a and b are [1, 2, 3]; c is still [1, 2]
```

For numbers and strings, aliasing never shows, because they can't be changed in place: `x += 1` makes a new number
and points `x` at it, leaving any other name where it was.

A copy made this way is **shallow**: a new outer list, holding the same items. If the items are lists themselves,
the copy and the original share them. `copy.deepcopy(a)` (after `import copy`) copies all the way down.

Passing a list to a function passes the object, not a copy. The parameter is one more name for the caller's list, so
a function can change it. Pointing the parameter at a new list, though, only moves the function's own name:

```python
def add_bonus(scores):
    scores.append(10)    # changes the caller's list
    scores = [0]         # just points the local name somewhere else
```

One more consequence: a **default value** is made once, when `def` runs, and kept with the function. A default list
is therefore one list, shared by every call that leaves the argument out. Use `None` as the default and make the list
inside: `if items is None: items = []`.

</Section>

<KeyIdea>

**A name is an arrow to an object. `=` and passing an argument add arrows; they never copy.** Changes to a list show
through every name for it. `is` asks "the same object?", `==` asks "equal values?".

</KeyIdea>

`==` compares values: two separate lists with the same items are equal. `is` compares identity: it is `True` only
for two arrows to one box. Use `==` to compare contents, and `is` to ask whether a change through one name would show
through the other (and for `x is None`).

Python works out a default value once, when the `def` line runs, and keeps it with the function. For a number or a
string that's harmless. For a list, every call that leaves the argument out shares one list, which keeps whatever the
last call put in it. Make the default `None`, and a new list inside the function.

</Misconception>

<Section step="recap" title="What to remember">

- A name is an arrow to an object; `=` and passing arguments add arrows and never copy.
- A list changed through one name is changed for every name.
- `==` compares values; `is` asks whether it is the same object.
- `a.copy()`, `a[:]` and `list(a)` make shallow copies; `copy.deepcopy` copies all the way down.
- A default list is made once and shared by every call: use `None` and make the list inside.

</Section>
