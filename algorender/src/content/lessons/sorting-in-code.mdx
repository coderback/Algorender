<Section step="hook" title="Read code before you write it">

Most of programming is reading code: your own from last week, a library's, a colleague's. Yet beginners are usually handed a blank editor first. Classroom studies of an approach called **PRIMM** found that learners understand more when they first **predict** what working code does, **run** it to check, **investigate** it, **modify** it, and only then **make** their own.

That is the plan here, with bubble sort: the simplest sort that actually works. Pick Python, JavaScript or TypeScript; every step works in all three, and your choice is remembered.

</Section>

A pass carries the biggest remaining value all the way to the end, but a small value near the end moves left by only
**one** place per pass. So one pass sorts only lucky inputs; in the worst case bubble sort needs `n - 1` passes.

<Section step="modify" title="Change it: largest first">

<Misconception
  id="swap-overwrites"
  title="Two assignments swap a pair"
  probes={[
    {
      q: 'a = [7, 3]. The code runs a[0] = a[1], then a[1] = a[0]. What is a now?',
      choices: ['[3, 7]', '[3, 3]', '[7, 7]'],
      answer: 1,
      trap: 0,
      why: 'a[0] = a[1] makes a[0] 3 and loses the 7; a[1] = a[0] then copies 3 back. Both slots end up 3.',
    },
    {
      q: 'Which of these swaps a[j] and a[j + 1] correctly?',
      choices: ['a[j] = a[j + 1], then a[j + 1] = a[j]', 'a[j + 1] = a[j], then a[j] = a[j + 1]', 'tmp = a[j], then a[j] = a[j + 1], then a[j + 1] = tmp'],
      answer: 2,
      trap: 0,
      why: 'Whichever slot is written first loses its old value, so it has to be saved in tmp first. The first two both end with two copies of one value.',
    },
  ]}
>

`a[j] = a[j + 1]` overwrites `a[j]` before anything has saved it, so the next line, `a[j + 1] = a[j]`, copies the new
value straight back and both slots hold the same number. Save one side first (`tmp = a[j]`), or let the language swap
both at once: `a[j], a[j + 1] = a[j + 1], a[j]` in Python, `[a[j], a[j + 1]] = [a[j + 1], a[j]]` in JavaScript.

</Misconception>

<ExplainBack
  id="why-bubble-sort-works"
  prompt="How does bubble sort put an array in order, and why is it finished after n − 1 passes?"
  rubric={[
    'Each pass compares neighbouring pairs from left to right and swaps any pair that is out of order.',
    'A pass carries the biggest value not yet in place all the way to the end.',
    'So after each pass one more value is final at the end, and the sorted part grows from the right.',
    'After n − 1 passes only the first value is left, and it must be the smallest, so the whole array is sorted.',
  ]}
  example="Bubble sort walks along the array comparing each pair of neighbours and swapping them when the left one is bigger. Once a pass reaches the biggest value still out of place, every comparison after that pushes it one step right, so it ends the pass at the end, where it belongs. Each pass therefore fixes one more value at the end, and the next pass can stop before it. After n − 1 passes, n − 1 values are in their final places, so the one left at the front must be the smallest and the array is sorted."

<Section step="recap" title="Recap">

- Read before you write: predict, run, investigate, modify, then make.
- One pass of bubble sort carries the biggest remaining value to the end, so after `i` passes the last `i` values are final.
- One comparison decides the order, and one swap fixes a pair. Flip the comparison to reverse the order.
