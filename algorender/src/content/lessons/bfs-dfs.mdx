<Section step="hook" title="Ripples, or a ball of string">

Drop a stone in a pond and the ripple reaches everything one step out before anything two steps out. Explore a maze
with a ball of string and you do the opposite: follow one passage to its end, and only then wind back to the last
junction with a passage you haven't tried.

Those are the two classic ways to visit every node a start can reach in a graph. **Breadth-first search** (BFS)
spreads out in rings, so it finds the route with the fewest edges to each node. **Depth-first search** (DFS) dives down
one path and backs up, the natural way to ask what can be reached, or whether the graph loops back on itself. What sets
them apart is where they keep the nodes still waiting: BFS in a queue, DFS in a stack.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="reachable">v is reachable from s when some path of edges leads from s to v. A search from s visits exactly these nodes.</Term>
  <Term name="discovered">A node is discovered the first time the search finds it, and marked at once, so no later edge adds it again.</Term>
  <Term name="frontier">The nodes found but not yet finished with: a queue in BFS, a stack in DFS. Exploring a node means looking at its neighbours.</Term>
  <Term name="level">The fewest edges on any path from the start: the start is level 0, its neighbours level 1, and so on.</Term>
  <Term name="parent">The node a node was discovered from. Parent links form a tree; in BFS, following them back from a node traces a shortest path.</Term>
  <Term name="backtrack">In DFS, stepping back along the current path when the node at its end has no undiscovered neighbours.</Term>
</Terms>

</Section>

<Section step="see" title="One graph, two orders">

This network has 8 nodes and 10 edges, and neighbours are read in alphabetical order. Run BFS from A and watch the
Queue panel: nodes join at the back and leave from the front.

<Explore slug="breadth-first-search" settings={{ preset: 'network' }} caption="BFS from A visits A, then B and C at level 1, D and E at level 2, F at level 3, and G and H at level 4. Edges to nodes already discovered are skipped." />

A's neighbours, B and C, join the queue first. B leaves and adds D behind C; then C leaves and adds E. So every level-1
node leaves before any level-2 node, and the queue never holds more than two neighbouring levels. That makes the levels
exact: when u, at level k, finds an undiscovered v, every node at a lower level has already been explored, and if v
were next to any of them it would have been found then. So no path reaches v in fewer than k + 1 edges. The parents
back from H in the Levels and parents table give H, F, D, B, A: four edges, and no path is shorter.

Now DFS on the same graph. It is recursive: it calls DFS on a node as soon as it discovers it, and the Call stack panel
holds the path from A to the current node.

<Explore slug="depth-first-search" settings={{ preset: 'network' }} caption="DFS from A goes A, B, C, E, F, D. D has nothing new, so DFS backtracks to F and goes on to G, then H. It reaches D along A–B–C–E–F–D, five edges, though A–B–D takes two." />

B's list does hold D, but C comes first, so by the time DFS returns to B, D is finished. On the way down, when C looks at
A, A is still on the call stack: that edge closes the loop A–B–C–A. It is called a back edge, and it is how DFS finds
cycles.

In both runs Edges examined ends at 20: each list is read once, so each edge is read once from each end. Both take
O(V + E) with adjacency lists, and O(V²) with a matrix, whose rows have V cells (see
[representing graphs](/learn/graph-representations)). Extra memory is O(V): a mark per node, plus the queue or the call
stack.

<KeyIdea>

**Both searches take a node from the frontier and look at its neighbours. With a queue, the oldest node
comes out first, so BFS explores in order of distance and first reaches each node along a path with the fewest edges.
With a stack, the newest comes out first, so DFS follows one path as deep as it goes before backing up.** Each node is
handled once, and each edge once from each end: O(V + E).

</KeyIdea>

</Section>

<Misconception
  id="mark-when-dequeued"
  title="Mark a node as visited when it leaves the queue"
  probes={[
    {
      q: 'A is joined to B, C and D, and each of those to E. A BFS from A marks nodes only as they leave the queue. How many times does E join it?',
      choices: ['Once', 'Three times: B, C and D each find it before it leaves', 'Five times'],
      answer: 1,
      trap: 0,
      why: 'E is unmarked while B, C and D are explored, so each adds it. Marking E when B finds it keeps it to one entry.',
    },
    {
      q: 'One BFS marks a node when it joins the queue, another when it leaves. Which is true?',
      choices: ['Both queue every node exactly once', 'The second can queue a node once per edge that finds it before it leaves', 'The second visits in depth-first order'],
      answer: 1,
      trap: 0,
      why: 'Until a node is marked, every edge into it looks like a new discovery, so the second queues it again each time: up to O(E) entries.',
    },
  ]}
>

Mark a node as it joins the queue, and every later edge into it is turned away. Marked only when it leaves, a node is
queued again by every edge that reaches it before then: in the square, B and D would both queue C. On a dense graph
that is O(E) entries instead of V, and unless each is checked as it comes out, the same node is explored over and over.

</Misconception>

DFS is simplest written recursively, as in its visualiser's code: mark u, then call DFS(v) for each unmarked neighbour
v. The calls wait on the call stack (see [recursion](/learn/recursion)), so a path of 100,000 nodes nests 100,000
calls, far past Python's default limit of 1,000. An explicit stack avoids that: pop a node, skip it if visited,
otherwise mark it and push its unmarked neighbours, each list in reverse so the first is on top. A node can be pushed
more than once, so the stack can hold O(E) entries, but only its first pop counts, which keeps the recursive order;
push in list order and the route changes.

Either way, DFS reaches every node it can, but not always by the shortest route.

>

DFS reaches each node along the first path its neighbour order happens to lead down, and nothing makes that path short:
on the network it took five edges to reach D, which is two from A. Its tree edges give **a** way to every reachable
node, not necessarily the shortest. For the fewest edges, use BFS.

</Misconception>

Each search has its jobs. BFS answers "how few steps?": the fewest hops between two people, the fewest moves in a
puzzle, how fast something spreads (several starts at level 0 give each node its distance to the nearest). DFS answers
"can I get there?" and "is there a loop?": filling regions, finding cycles, and
[topological sort](/learn/topological-sort), ordering tasks so each comes after what it depends on. Neither goes beyond what its start can
reach.

<Explore slug="breadth-first-search" settings={{ preset: 'components' }} caption="BFS from A discovers B and C at level 1 and D at level 2, then the queue runs dry. E, F and G are never discovered: no edge joins them to A's group." />

To visit a whole graph, start a new search from each node not yet discovered. In an undirected graph each start opens
another **connected component**, and the total is still O(V + E).

The last trap is weights.

  id="bfs-weighted"
  title="BFS finds the shortest route in a weighted graph too"
  probes={[

      answer: 1,
      trap: 0,
      why: 'BFS counts roads, and one road to B beats two. But 1 + 1 = 2 km through C is shorter than the 5 km road.',
    },
    {
      q: 'Which algorithm finds the shortest distances when roads have different lengths, none of them negative?',
      choices: ['Breadth-first search', 'Dijkstra’s algorithm', 'Depth-first search'],

      trap: 0,
      why: 'BFS treats every edge as one step, so it finds the fewest roads, not kilometres. Dijkstra takes nodes in order of total distance, using a priority queue.',

>

BFS never reads a weight. Its levels are the fewest edges, which is the shortest distance only when every edge costs the
same. With different weights, more edges can cost less. [Dijkstra's algorithm](/learn/dijkstra) keeps the shape of BFS
but swaps the queue for a priority queue, so nodes come out in order of total distance.

</Misconception>

<Section step="recap" title="What to remember">

- BFS keeps its frontier in a queue, so it explores every node one edge away before any two away. Its levels are the
  fewest edges from the start, the shortest distance only when edges are unweighted.
- DFS keeps a stack, usually the call stack: it dives down one path and backtracks when stuck. It finds a path, not
  always the shortest, and an edge to a node still on the stack, other than the edge it came in on, closes a cycle.
- In BFS, mark a node the moment it is discovered, so it joins the queue once. Both take O(V + E) with adjacency
  lists, O(V²) with a matrix, and O(V) extra memory. Neighbour order decides the visit order.
- A search reaches only what its start can reach; start again from each undiscovered node to cover every component.
- Next: [topological sort](/learn/topological-sort), [Dijkstra's algorithm](/learn/dijkstra) for weighted edges, [minimum spanning trees](/learn/minimum-spanning-trees)
  and [strongly connected components](/learn/strongly-connected-components). Write both searches in [Write breadth-first search](/code/bfs-levels) and
  [Write depth-first search](/code/dfs-order), then practise with [Count the Islands](/practice/number-of-islands), a
  search per island, and [Spreading Rot](/practice/rotting-oranges), a BFS from every rotten orange at once.

</Section>
