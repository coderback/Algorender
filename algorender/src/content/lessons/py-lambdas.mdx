<Section step="hook" title="Functions are values too">

`max("zoo", "apple", "kiwi")` gives `zoo`, the one that comes last in the alphabet. What if you want the longest word
instead? You don't need a new `max`. You hand it a function that says what to compare by: `max("zoo", "apple",
"kiwi", key=len)` gives `apple`. A function can be passed around like any other value, and a **lambda** lets you
write a small one right where you need it.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="function object">What `def` makes: a value like a number or a string, which a name points at. In the memory view it has a box of its own.</Term>
  <Term name="lambda">An expression that makes a small function without a name: `lambda x: x * 2`.</Term>
  <Term name="key=">An argument that `max`, `min` (and `sorted`, later) take: a function they call on each item, comparing what it gives back.</Term>
</Terms>

A function's name, without brackets, is the function itself; with brackets, it's a call. `print(len)` shows something
like `<built-in function len>`, while `print(len("hi"))` shows `2`. So you can pass a function to another function,
which calls it when it chooses:

```python
def apply_twice(f, x):
    return f(f(x))

def double(n):
    return n * 2

apply_twice(double, 5)   # double(double(5)), which is 20
```

Pass `double`, not `double()`: the brackets would call it on the spot, with no argument.

A `lambda` writes the same kind of small function in one expression:

```python
double = lambda n: n * 2          # the same as the def above
apply_twice(lambda n: n + 3, 1)   # 7, with no name needed
```

After `lambda` come the parameters, then a colon, then **one expression**, which the function gives back when it is
called. There is no `return` in a lambda (writing one is a `SyntaxError`), and no room for loops or other statements:
anything longer deserves a `def` and a name.

A function made inside another keeps the names it uses from there, as you saw with closures, and lambdas are no
different: `make_adder(3)` below returns a lambda that remembers `n` is 3.

</Section>

Brackets call a function. `use(half)` hands `use` the function, to call when it chooses. `use(half())` calls `half`
straight away, with no arguments. If `half` needs an argument, that's a `TypeError` on the spot, and `use` never runs;
if not, `use` gets whatever `half` gave back (often `None`), not the function. When you pass a function, leave the
brackets off.

</Misconception>

<Misconception
  id="lambda-return"
  title="A lambda needs the word return"
  probes={[

A lambda's body is a single expression, and calling the lambda gives back that expression's value. You never write
`return` in one; Python won't accept it. If the function needs more than one expression, write it with `def`.

</Misconception>

<Section step="recap" title="What to remember">

- A function is a value: its name without brackets is the function, with brackets it's a call.
- Functions can be passed to other functions, and returned from them.
- `lambda params: expression` makes a small function that gives back its expression; no `return`.
- `max`, `min` and later `sorted` take `key=`, a function to compare by.

</Section>
