<Section step="hook" title="Naming a piece of work">

Say a program works out the area of three rooms. You could write `width * height` three times, but if the rule ever
changes (add the doorway, round up), you'd have to fix it in three places. A **function** gives a piece of work a
name. You write it once, then use it by name as often as you like, each time with different values.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="def">The line that makes a function: `def area(width, height):`, then its body, indented under it.</Term>
  <Term name="parameter">A name in the `def` line's brackets, like `width`. It stands for whatever value the call passes in.</Term>
  <Term name="call">Using the function: `area(3, 4)`. Its body runs, with `width` pointing at 3 and `height` at 4.</Term>
  <Term name="argument">A value a call passes in, like the `3` and the `4` in `area(3, 4)`.</Term>
  <Term name="return">Ends the call and hands a value back to the line that made it.</Term>
  <Term name="None">The value a call gives back when the function ends without a `return` value.</Term>
</Terms>

```python
def area(width, height):
    return width * height

print(area(3, 4))      # 12
big = area(10, 20)     # big points at 200
```

The `def` line runs when Python reaches it (here, once), and all it does is make the function and point the name
`area` at it. Nothing in the body runs yet. The body runs each time something **calls** `area`, and each call gets
its own `width` and `height`.

`return` does two things at once: it hands a value back to the line that called, and it ends the call. A line after
a `return` in the same block never runs. A function that reaches the end of its body without a `return` value gives
back `None`, Python's value for "nothing", and so does `return` on its own, with no value after it: it just ends the
call.

You'll also meet `pass`, a line that does nothing at all. A body can't be empty, so task starters use `pass` to hold
the place where your code goes: replace it.

`print` and `return` are easy to mix up. `print` shows a value on the screen; the program can't do anything more
with it. `return` gives the value back to the program, so a line like `big = area(10, 20)` can keep it, add to it, or
pass it on.

</Section>

<KeyIdea>

**A call runs the function's body with its own names, then hands back what `return` gives**, or `None` when there's
no `return` value. Printing a value inside a function is not the same as returning it.

</KeyIdea>

    },

>

`print` shows a value on the screen, and that's all: the line that called the function gets nothing back but
`None`. To hand a value back so the program can keep it and use it, the function has to `return` it. If you see
`None` where you expected a number, look for a `print` that should have been a `return`.

</Misconception>

`return` ends the call at once, even in the middle of a loop. Nothing after it in the function runs on that call.
That is often exactly what you want: a function that searches can `return` the moment it finds the answer.

</Misconception>

<Section step="recap" title="What to remember">

- `def` makes a function; its body runs each time it is called, with the call's own names.
- Arguments fill the parameters; `return` hands a value back and ends the call.
- A function without a `return` value gives back `None`.
- `print` shows a value; only `return` gives it back to the program.

</Section>
