<Section step="hook" title="Each thing once">

Which different words appear in a story? Which numbers did two players both pick? Have I seen this name before? A list
keeps every copy, and checking a long list means looking at its items one by one. Python's **set** keeps each value
once, and tells you straight away whether a value is in it.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="set">A collection that holds each value at most once, in no order: `{"red", "green"}`.</Term>
  <Term name="duplicate">A second copy of a value that is already there. A set drops duplicates.</Term>
  <Term name="membership">Whether a value is in a collection: `x in s` is `True` or `False`.</Term>
  <Term name="union, intersection, difference">Ways to combine two sets: everything in either, only what is in both, and what is in the first but not the second.</Term>
</Terms>

Write a set with curly brackets, like a dict without the colons, or make one from a list with `set(...)`. Either way,
duplicates go:

```python
colours = {"red", "green", "red"}
print(len(colours))        # 2: the second "red" was dropped
nums = set([3, 1, 3, 2, 1])
print(sorted(nums))        # [1, 2, 3]
print(2 in nums)           # True
```

`sorted(...)` gives a new list of a collection's items, smallest first (A to Z for words), so it shows a set's items in a
fixed order. `set("hello")` works too: it's the set of the string's letters, with one `l`. And `x in s` is fast for the same reason a
dict finds a key fast: Python jumps straight to where `x` would be kept. So a set's items follow the dict-key rule: they
must be values that can't change, like numbers, strings and tuples. `{[1, 2]}` is a `TypeError` that says a list is
"unhashable", Python's word for a value it can't file away like this.

A set can grow and shrink:

```python
s = {1, 2}
s.add(2)          # already there: nothing changes
s.add(5)          # s now holds 1, 2 and 5
s.remove(1)       # takes 1 out; a KeyError if it isn't there
s.discard(9)      # takes 9 out if it's there; never an error
```

Three operators combine two sets into a new one:

```python
a = {1, 2, 3}
b = {2, 3, 4}
print(sorted(a | b))   # union, in either:        [1, 2, 3, 4]
print(sorted(a & b))   # intersection, in both:   [2, 3]
print(sorted(a - b))   # difference, in a not b:  [1]
print(sorted(b - a))   #                          [4]
```

Difference keeps what is in the **first** set, so `a - b` and `b - a` differ.

Two traps. `{}` is an empty **dict**, not a set: dicts had the curly brackets first. An empty set is `set()`, which is
also how Python prints one; `{}.add(4)` stops with an `AttributeError`, Python's error for a method a value doesn't
have. And a set has no order and no positions: `s[0]` is a `TypeError`, and the order a set prints in, or a `for` loop
visits, isn't the order you added things. Whenever order matters, use `sorted(s)`.

</Section>

<Section step="recap" title="What to remember">

- A set holds each value once: `set(a_list)` drops duplicates, and adding a value already there changes nothing.
- `x in s` is a fast yes or no; a set's items must be values that can't change, like a dict's keys.
- `add` puts an item in; `remove` takes one out or raises a `KeyError`; `discard` takes it out if it's there.
- `a | b` is in either, `a & b` in both, `a - b` in `a` but not `b`.
- `{}` is an empty dict; an empty set is `set()`.
- A set has no order and no indexes: print `sorted(s)` when order matters.

</Section>
