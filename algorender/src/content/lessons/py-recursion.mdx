<Section step="hook" title="A function that calls itself">

How many digits are in 9045? One for the 5, plus however many are in 904. And 904 is one digit plus the digits of
90, and so on, until a single digit is left. Some problems are made of a smaller copy of themselves. A function can
solve them by calling **itself** on the smaller copy, until the copy is so small that the answer is obvious.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="recursive function">A function that calls itself, on a smaller version of its problem.</Term>
  <Term name="base case">The case small enough to answer without another call. Every recursive function needs one, and every call must get closer to it.</Term>
  <Term name="recursive case">The case that calls the function again, on a smaller problem, and uses its answer.</Term>
  <Term name="call stack">The frames of the calls still running, newest on top. Each call waits there until the call it made returns.</Term>
</Terms>

```python
def factorial(n):
    if n <= 1:                       # base case
        return 1
    return n * factorial(n - 1)      # recursive case

factorial(3)   # 3 * factorial(2) = 3 * (2 * factorial(1)) = 3 * 2 * 1 = 6
```

Nothing special happens when a function calls itself: it's a call like any other. Python makes a new frame with its
own `n`, and the calling frame **waits**, its own `n` unchanged, until the new call returns. `factorial(3)` waits for
`factorial(2)`, which waits for `factorial(1)`. That one hits the base case and returns 1, and then the waiting calls
finish one by one, newest first, each using the answer it was given.

Without a base case, or with a call that doesn't get closer to it, the calls never stop. Python allows about a
thousand calls waiting at once, then stops the program with `RecursionError: maximum recursion depth exceeded`.

A function can do work both before and after its call to itself. Work before the call happens on the way down, in the
order the calls are made. Work after it happens on the way back up, in the reverse order.

</Section>

<KeyIdea>

**Each call gets its own frame and its own names, and waits for the call it made.** A base case stops the calls;
then they return one by one, newest first.

</KeyIdea>

      answer: 0,
      trap: 1,

    },

>

A call to itself is still a new call, with a new frame and fresh names. The calling frame keeps its own `n` while it
waits. When the inner call returns, the caller carries on with its own `n`, exactly as it was. In the memory view,
that's a stack of frames, each with an `n` of its own.

</Misconception>

<Section step="recap" title="What to remember">

- A recursive function calls itself on a smaller problem.
- Each call has its own frame and names, and waits for the call it made.
- A base case answers without calling; every call must get closer to it, or Python stops with a `RecursionError`.
- Work before the call happens on the way down; work after it, on the way back up.

</Section>
