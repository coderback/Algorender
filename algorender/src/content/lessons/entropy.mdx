<Section step="hook" title="How much is a message worth?">

"It's sunny in the desert" tells you almost nothing; "it's snowing in the desert" is news. Information is **surprise**:
the less likely an outcome, the more you learn when it happens.

In 1948 Claude Shannon turned that into a number, measured in bits. It sets the limit on how far any file can be
compressed, and its cousin, **cross-entropy**, is the loss function that trains almost every classifier and language model.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="surprise">$\log_2(1/p)$ bits for an outcome with probability $p$: 1 bit for a fair coin flip, 3 bits for a 1-in-8 event.</Term>
  <Term name="entropy H(P)">The average surprise of a distribution $P$: $\sum_x p(x)\log_2\frac{1}{p(x)}$.</Term>
  <Term name="cross-entropy H(P, Q)">The average surprise when outcomes follow $P$ but you expected $Q$.</Term>
  <Term name="KL divergence">$H(P, Q) - H(P)$: the extra bits you pay for believing $Q$. Never negative.</Term>
</Terms>

</Section>

<Section step="see" title="Measure the weather in bits">

<Explore slug="entropy" settings={{ preset: 'weather' }} caption="Each outcome's surprise is log₂(1/p); the entropy is their average, weighted by how often each happens." />

Sun (1/2) is worth 1 bit, cloud (1/4) 2 bits, rain and snow (1/8) 3 bits each. Weighted by how often each happens, the
average is $0.5 \cdot 1 + 0.25 \cdot 2 + 0.125 \cdot 3 + 0.125 \cdot 3 = 1.75$ bits. The code 0, 10, 110, 111
achieves exactly that: short codes for common outcomes.

A forecaster who thinks all four are equally likely ($Q$ uniform) uses 2 bits each, so they pay $2 - 1.75 = 0.25$ extra
bits per day. That gap is the KL divergence.

<KeyIdea>

**Cross-entropy = entropy + KL divergence.** Training a model to minimise cross-entropy against the data is the same as
minimising how far its beliefs $Q$ are from the truth $P$, because $H(P)$ doesn't depend on the model.

</KeyIdea>

</Section>

- Make $P$ uniform: entropy reaches its maximum, $\log_2 n$.
- Make one outcome almost certain: entropy drops towards 0.
- Pull one of $Q$'s bars down to zero while $P$'s stays up: KL shoots to infinity.

      q: 'Which statement about KL divergence is right?',
      choices: ['KL(P‖Q) = KL(Q‖P), like a distance', 'KL can be negative when Q is better than P', 'KL(P‖Q) is never negative, and it can differ from KL(Q‖P)'],
      answer: 2,
      trap: 0,
      why: 'Gibbs’ inequality makes KL at least 0, with 0 only when the distributions match. But it is not symmetric, so it is not a distance in the usual sense.',

>

It measures how different two distributions are, but it isn't symmetric: $KL(P\|Q)$ and $KL(Q\|P)$ are usually
different, and one can be infinite while the other is finite. Which way round you use it changes what a model learns.

</Misconception>

<Misconception
  id="surprise-not-log"
  title="An outcome’s surprise is 1/p"
  probes={[
    {
      q: 'Two fair coins both land heads, which has probability ¼. How many bits of surprise is that?',
      choices: ['4', '2', '¼', '1'],
      answer: 1,
      trap: 0,
      why: 'log₂(1/¼) = log₂ 4 = 2 bits: one bit for each coin. Surprise adds up over independent events, which is why it is a logarithm.',
    },
    {
      q: 'An outcome has probability 1/8. How many bits of surprise is it?',
      choices: ['1/8', '8', '3', '0.375'],
      answer: 2,
      trap: 1,
      why: 'log₂(8) = 3 bits. It takes three yes/no questions to pick one of eight equally likely outcomes.',
    },
  ]}
>

Rarer outcomes are more surprising, but surprise is $\log_2(1/p)$, not $1/p$. Two independent coin flips are 1 bit each,
so both together must be 2 bits. Their probability is ¼, and $\log_2 4 = 2$, while $1/p$ would give 4, not the 1 + 1
the two flips are worth. The logarithm is what makes the surprise of independent events add up.

</Misconception>

<Section step="recap" title="What to remember">

- Surprise is $\log_2(1/p)$ bits; entropy is the average surprise, at most $\log_2 n$ for $n$ outcomes.
- Cross-entropy is the average surprise under a model; KL is its excess over the entropy, never negative.
- A model that rules out something that can happen pays infinite cross-entropy.
- Machine learning minimises cross-entropy, which is the same as minimising KL from the data.

</Section>
