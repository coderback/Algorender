<Section step="hook" title="Tidying up text">

Text that comes from people is messy. Someone types `  Yes ` with spaces round it, or `YES` in capitals, and your
`if answer == "yes":` says no. A line like `3,4,5` holds three numbers but arrives as one string. Strings come with
tools for tidying, splitting, joining and searching, and they all follow one rule that people trip over: a string
never changes.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="method">A function that belongs to a value, called with a dot after it: `word.upper()`. You've met list methods such as `append`; strings have their own.</Term>
  <Term name="whitespace">The characters you can't see: spaces, tabs and the newline at the end of a line. Inside quotes, `\t` writes a tab and `\n` a newline.</Term>
  <Term name="separator">The text that goes between pieces: the comma in `3,4,5`, or the `", "` you put between words when joining them.</Term>
</Terms>

Strings are immutable: once made, they can't change. So a string method never changes the string it's called on. It
**gives back a new string**, and the old one stays as it was:

```python
s = "  Hello  "
t = s.strip()                # t is 'Hello': whitespace gone from both ends
print(t.upper())             # HELLO
print(t.replace("l", "L"))   # HeLLo
print(len(s), len(t))        # 9 5: s still has its spaces
```

`lstrip()` and `rstrip()` strip one end only, and `lower()` makes small letters. A line like `s.strip()` on its own
makes the new string and throws it away; to keep it, write `s = s.strip()`. That's the opposite of a list, whose
`append` changes the list and gives back `None`.

**Splitting** cuts a string into a list of strings:

```python
"a  b\tc\n".split()        # ['a', 'b', 'c']
"a,,b".split(",")          # ['a', '', 'b']
"2024-11-20".split("-")    # ['2024', '11', '20']
```

With nothing in the brackets, `split()` cuts at any run of whitespace and never gives empty pieces: the right choice
for words. Given a separator, it cuts at exactly that text and keeps the rest, spaces and empty pieces included.

**Joining** goes the other way. The separator comes first, and the list goes in the brackets:

```python
" ".join(["a", "b", "c"])  # 'a b c'
", ".join(["tea", "milk"]) # 'tea, milk'
```

Every item must be a string: `",".join([1, 2])` stops with a `TypeError`. Turn numbers into text first, for example
with a comprehension: `"/".join([str(d) for d in [20, 11, 2024]])` is `"20/11/2024"`.

**Searching** asks where, how many, or whether:

```python
t = "banana"
t.find("an")         # 1: where it first starts
t.find("x")          # -1: not there
t.index("x")         # ValueError: substring not found
t.count("a")         # 3
t.startswith("ban")  # True (and endswith works the same way at the end)
"2024".isdigit()     # True: at least one character, and all of them digits
```

When the text isn't there, `find` gives back `-1` but `index` stops the program, so use `find` when "not there" is a
normal answer. `isdigit()` is a handy check before `int()`, though it says `False` for `"-5"` and `"3.5"`. Slices
work on strings as on lists: `"hello"[1:4]` is `"ell"`.

Because each method gives back a string, you can **chain** them, left to right: `"  Tea, MILK ".strip().lower()`
strips, then lowers what strip gave back.

</Section>

<Section step="recap" title="What to remember">

- Strings never change: a method gives back a new string, so keep it with `s = s.strip()`.
- `strip`, `lower`, `upper` and `replace` tidy text; chain them, reading left to right.
- `split()` cuts at any whitespace and drops empty pieces; `split(",")` cuts at exactly each comma and keeps the rest.
- `"sep".join(items)`: the separator calls it, and every item must be a string.
- `find` gives `-1` when the text isn't there, while `index` stops with a `ValueError`; `count`, `startswith`,
  `endswith` and `isdigit` answer the other questions.

</Section>
