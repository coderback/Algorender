<Section step="hook" title="When a program meets bad input">

A program asks for your age and you type `twelve`. `int("twelve")` can't make a number from that, so the program
stops with a `ValueError`. Here you'll learn to read errors like that, and to **catch** the ones you
expect, so the program can say "please type a number" and carry on.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="exception">An error Python meets while running, such as `ValueError`. Python **raises** it: it stops the line it was on and looks for code that handles it.</Term>
  <Term name="traceback">What Python prints when nothing handles an exception: the calls that led to it, then the error's type and message.</Term>
  <Term name="try / except">Run the `try` block; if it raises an exception of the type named, run the `except` block instead of stopping.</Term>
</Terms>

**Reading a traceback.** Start at the bottom and work up. Here a function, `per_person`, shares 12 sweets among 0
people:

```text
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    print(per_person(12, 0))
          ~~~~~~~~~~^^^^^^^
  File "main.py", line 2, in per_person
    return total // people
           ~~~~~~^^~~~~~~~
ZeroDivisionError: division by zero
```

The last line says **what** went wrong: the type and a message. Just above it is **where**: line 2, inside
`per_person`, which line 4 called.

The types you'll meet most: `ValueError` (a right type but wrong value, `int("hi")`), `TypeError` (the wrong type,
`"3" + 4`), `KeyError` (no such key in a dictionary), `IndexError` (no such position in a list), `ZeroDivisionError`
and `NameError` (a name never set, often a typo).

**Catching one.** Put the line that might fail in a `try` block, and what to do about it in an `except` block:

```python
text = input()
try:
    n = int(text)
    print("Double:", n * 2)
except ValueError:
    print("Not a whole number:", text)
print("Done")
```

For `seven`, `int(text)` raises, so Python leaves the `try` block **at that line**, skipping the `print` under it,
and runs the `except` block, then `print("Done")`. Nothing goes back to finish the `try` block.

**Several kinds.** Give each type its own `except`; Python runs the first that matches. `as e` points `e` at the
exception, so you can print its message:

```python
prices = {"tea": 2, "cake": 3}
try:
    item = input()
    count = int(input())
    print(prices[item] * count)
except KeyError as e:
    print("We don't sell", e)
except ValueError as e:
    print("Bad count:", e)
```

For `pie` it prints `We don't sell 'pie'`. A type with no `except` of its own still stops the program.

**else and finally.** Two more blocks may follow the `except`s, in this order: `else` runs only when the `try`
block raised nothing, so the `try` can hold just the risky line, and `finally` runs last, every time.

**Ask until it works.** Put the `try` inside `while True:`. The `break` is only reached when `int(...)` worked:

```python
while True:
    try:
        age = int(input("Age: "))
        break
    except ValueError:
        print("Please type a whole number.")
```

**Catch only what you expect.** A bare `except:` catches **every** error (`except Exception:` nearly every one),
your own mistakes too:

```python
try:
    total = int(input())
    print(totl * 2)
except:
    print("Please type a number.")
```

Type `5` and it says `Please type a number.` The real error was the typo `totl`, a `NameError`. With
`except ValueError:` the typo stops the program with `NameError: name 'totl' is not defined. Did you mean: 'total'?`,
pointing at the line to fix.

The moment a line in a `try` block raises, Python leaves the block: the lines after it are skipped, the matching
`except` runs, and the program carries on **after** the whole `try`.

<Section step="recap" title="What to remember">

- Read a traceback from the bottom up: the type and message, then the line that raised it.
- When a line in a `try` block raises, the rest of the block is skipped and the first matching `except` runs.
- `except ValueError as e:` names the exception, so you can print its message.
- `else` runs only when nothing was raised; `finally` runs every time.
- Catch only the types you expect: a bare `except:` or `except Exception:` hides your own bugs.

</Section>
