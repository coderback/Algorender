<Section step="hook" title="Looking things up by name">

Your phone doesn't make you remember that Ann is contact number 14: you type her name and get her number. A list
finds things by position, which is no help when you only know the name. A **dictionary** finds a value by a **key**
you choose, such as a name or a word.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="dictionary">A collection of key–value pairs in curly brackets: `{"ann": 31, "bob": 27}`. Python calls it a `dict`. You look values up by key, not by position.</Term>
  <Term name="key">What you look a value up by: `"ann"`. It must be a value that can’t change, such as a string, a number or a tuple.</Term>
  <Term name="value">What a key leads to: `31`. Values can be anything, and two keys can share one.</Term>
  <Term name="KeyError">The error from reading a key the dict doesn’t have.</Term>
</Terms>

Square brackets with a key read a value, add a pair, or change one:

```python
ages = {"ann": 31, "bob": 27}
print(ages["ann"])     # 31: look a value up by its key
ages["cy"] = 19        # a new key: the pair is added
ages["bob"] = 28       # a key already there: its value changes
print(ages)            # {'ann': 31, 'bob': 28, 'cy': 19}
print(len(ages))       # 3: the number of pairs
```

A key is in a dict at most once, so assigning to `"bob"` again replaces his value, and he keeps his place: the pairs
stay in the order their keys were first added.

`in` asks about the **keys** only: `"ann" in ages` is `True`, but `31 in ages` is `False` (`31 in ages.values()`
asks about the values). `not in` asks the opposite: `"dan" not in ages` is `True`.

Reading a missing key, `ages["dan"]`, stops the program with `KeyError: 'dan'`; it doesn't give `None`. Check first
with `if "dan" in ages:`, or use `get`: `ages.get("dan")` gives `None`, and `ages.get("dan", 0)` gives `0`, a default
you choose. `get` only reads; it never adds the key. `del ages["cy"]` takes a pair out, and `ages.pop("cy")` does
too, giving back its value.

A `for` loop over a dict visits its **keys**, in order. `.values()` gives the values, and `.items()` gives each pair as
a tuple, which you can unpack:

```python
ages = {"ann": 31, "bob": 28}
for name in ages:                 # the keys: ann, then bob
    print(name, ages[name])
for name, age in ages.items():    # each pair, unpacked
    print(name, "is", age)
```

`get` with a default makes counting easy: a new word is stored as 0 + 1, and a word seen before adds one to its
count:

```python
counts = {}
for word in ["red", "blue", "red"]:
    counts[word] = counts.get(word, 0) + 1
print(counts)   # {'red': 2, 'blue': 1}
```

A dict files each pair by its key, so a key mustn't change later. Strings, numbers and tuples can be keys (a grid point
like `(0, 0)` makes a good one), but `{[0, 0]: "start"}` stops with `TypeError: cannot use 'list' as a dict key
(unhashable type: 'list')`.

</Section>

<KeyIdea>

**A dict maps each key to one value: `d[k]` reads, adds or changes by key, and `in` and `for` look at the keys.**
Reading a missing key with `d[k]` is a `KeyError`; `d.get(k, default)` is the safe way to read.

</KeyIdea>

On a dict, `in` asks whether something is one of the **keys**, as you would ask a phone book whether a name is in it.
It never looks at the values; to ask about those, say so: `x in d.values()`.

A plain `for` loop over a dict gives its keys, in the order they were added, whatever you name the loop's variable.
Loop over `d.values()` for the values, or `for k, v in d.items():` for both.

<Section step="recap" title="What to remember">

- A dict maps keys to values: `d[k]` reads, and `d[k] = v` adds the pair or changes its value.
- `in` and a plain `for` loop look at the keys; use `.values()` for the values and `.items()` for the pairs.
- Reading a missing key is a `KeyError`, not `None`: check with `in`, or use `d.get(k, default)`.
- `del d[k]` and `d.pop(k)` take a pair out; the rest stay in the order their keys were added.
- Count with `counts[x] = counts.get(x, 0) + 1`.
- Keys must be unchangeable: strings, numbers and tuples, never lists.

</Section>
