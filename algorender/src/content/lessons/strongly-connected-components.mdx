<Section step="hook" title="Can you get back?">

In a town of one-way streets, driving from the station to the market doesn't mean you can drive back. Some junctions
form a tangle where you can get from any of them to any other and home again; leave it by the wrong street and there may
be no way back in.

Those tangles are a directed graph's **strongly connected components**: the largest groups of nodes that can all reach
each other. A plain [depth-first search](/learn/bfs-dfs) can't pick one out: from a node it reaches everything
downstream, including nodes with no way back. **Kosaraju's algorithm** uses two searches, the second with every edge
turned round; **Tarjan's** manages with one.

</Section>

<Section step="parts" title="The pieces you will see">

<Terms>
  <Term name="strongly connected">Nodes u and v are strongly connected when a path leads from u to v and another leads back.</Term>
  <Term name="strongly connected component (SCC)">A largest group of nodes that are all strongly connected. Every node is in exactly one; a node on no cycle is a component by itself.</Term>
  <Term name="condensation">Each SCC squashed into one node, with an edge wherever an edge joins two components. It has no cycles: it is a DAG.</Term>
  <Term name="source and sink">A source component has no edges coming in from other components; a sink has none going out.</Term>
  <Term name="finishing order">The order a depth-first search finishes nodes in: each after every node its search went on to discover.</Term>
  <Term name="reversed graph">Every edge turned round. A path from u to v becomes one from v to u, so the SCCs stay the same.</Term>
</Terms>

</Section>

<Section step="see" title="Two searches, the second one backwards">

This graph has three components: A, B and C; D, E and F; G and H. B → D and G → F lead into D, E and F, and no edge
leads out of them. Neighbours are taken in alphabetical order. In the first pass, each node goes on top of S as it
finishes.

<Explore slug="kosaraju" settings={{ preset: 'three' }} caption="The first pass searches from A, finishing C, F, E, D, B and A, then from G, finishing H and G, so G ends on top of S. Then the edges turn round and nodes are popped. G's search collects H: S1 = {G, H}. A's collects C and B: S2 = {A, B, C}. D's collects F and E and turns back at B and G, which are already placed: S3 = {D, E, F}." />

A node finishes only after everything its search discovers, so D, E and F finish before B, which led into them.
Nothing from A reaches G, so the loop starts a second search there, and G finishes last.

That last finisher always lies in a **source** component, one that no other component points into. Suppose a
component X had an edge into G's. If the first pass entered X first, it reached G's component from there and finished
all of it before backing out of X. If it entered G's first, it could never reach X (or the two would be one
component), so it finished G's before visiting X. Either way a node of X finishes after G.

Now reverse every edge. Components keep their members, but the edges between them turn round, so the source becomes a
**sink**: a search from G can reach only G's own component. Each later search starts from the latest finisher still
unplaced, whose component is a source of what remains, so its reversed edges out lead only to components already
placed. The search skips those, which is why D's search turned back at B and G.

The components come out sources first, a topological order of the condensation. Each pass reads every node and edge
once (16 node visits and 20 edges examined here), and building the reversed
[adjacency lists](/learn/graph-representations) is one more sweep: O(V + E) in all.

<KeyIdea>

**The node a depth-first search finishes last lies in a source component. Reverse every edge and that component
becomes a sink, so a search from it collects exactly its own nodes.** Popping nodes in reverse finishing order and
searching the reversed graph from each one not yet placed peels off one SCC per search, in O(V + E).

</KeyIdea>

</Section>

The component on top is a source: nothing leads in, but edges may lead out, and a search along the original edges
follows them. From G in the first graph it would collect G, H, F, D and E. Reversed, the source is a sink, and the
search stays inside.

</Misconception>

**Tarjan's algorithm** finds the same components in one search. Each node gets an **index**, its place in the visit
order, and a **low-link**: the smallest index it can get back to through the search tree below it plus one more edge,
counting only nodes still on a stack S, where nodes stay after they finish until their component is known. A node that
finishes with its low-link equal to its index roots a component: pop S down to it, and those nodes are one SCC.

<Explore slug="tarjan" settings={{ preset: 'three' }} caption="The search from A gives A to F the indices 0 to 5. C → A drops C's low-link to 0, then B's on the way back; F → D drops F's to 3, then E's. D is the first to finish with its low-link equal to its index, so S pops down to D: {D, E, F}. A pops {A, B, C}, and a search from G pops {G, H}: 8 node visits and 10 edges examined, half Kosaraju's." />

Components close sinks first, where Kosaraju's came out sources first. G → F is ignored: F's component is finished
and can't reach back to G. Its extra memory is O(V); Kosaraju's reversed copy of the edges needs O(V + E).

The condensation never has a cycle (its components would merge), so SCCs are a common first step. Packages in one
component of a dependency graph depend on each other in a loop and must be built together; a
[topological sort](/learn/topological-sort) of the condensation orders the groups. In a follow network, a component is a
group of accounts that all reach each other. A 2-SAT solver turns each clause “a or b” into edges not-a → b and
not-b → a: the clauses can all hold exactly when no variable shares a component with its negation.

<Explore slug="kosaraju" settings={{ preset: 'dag' }} caption="The DAG the topological sort lesson ran DFS on. With no cycles, every node is a component of its own: the second pass pops A, C, B, D and E, one search each. That is the reverse finishing order, a topological order, since a DAG is its own condensation." />

A reaches every node of that DAG, and still every node is alone.

Strongly connected means reachable **both** ways. A search from u finds everything u reaches, across many components;
only the nodes that also reach u share its component. Ignoring the arrows gives weakly connected components instead.

</Misconception>

The opposite slip splits one component in two.

</Misconception>

<Section step="recap" title="What to remember">

- A strongly connected component is a largest group of nodes that all reach each other. Every node is in exactly one,
  a node on no cycle is alone, and reaching one way isn't enough.
- Squash each component to a node and the condensation is a DAG, which [topological sort](/learn/topological-sort)
  can order.
- Kosaraju's: the last node a DFS finishes lies in a source component. Reverse every edge and pop nodes in reverse
  finishing order: each search of the reversed graph collects exactly one SCC, sources first.
- Tarjan's: one DFS that gives each node an index and a low-link. A node whose low-link equals its index roots a
  component, popped off the stack in one go, sinks first.
- Both are O(V + E) with adjacency lists. SCCs find dependency cycles, groups in follow networks and 2-SAT answers.
- Practise with [Can Every Course Be Taken?](/practice/course-schedule), where a cycle means a component of two or
  more courses, and [Course Order](/practice/course-schedule-ii); write the search in
  [Write depth-first search](/code/dfs-order), or try your own graphs in the [Kosaraju](/visualisers/kosaraju) and
  [Tarjan](/visualisers/tarjan) visualisers.

</Section>
